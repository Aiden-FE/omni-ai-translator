# ADR-0002: 加速节点采用只缓存不代理的开放缓存模型

- **Status**: Accepted
- **Date**: 2026-10-07
- **Scope**: 插件加速能力 + `services/relay/`（设计）

## Context

需求原文：「设置后执行翻译前先将请求发往翻译加速域名，翻译加速服务将命中 Redis 缓存的结果翻译返回，未命中的不做处理。插件接到结果后将未命中的发往翻译接口，翻译接口返回后异步将结果提交翻译加速服务建立缓存。」

一个更省事的形状是让加速节点顺带代理翻译：插件只发一个请求，加速节点命中则返回缓存、未命中则自己调翻译接口再落缓存。代价是加速节点必须经手用户的 API Key 与目标翻译端点，凭据一旦进入第三方服务，插件的隐私承诺（见 `docs/privacy/index.html`「API Key 仅保存在浏览器本地」）即告失效，而且自建节点会变成用户模型的隐形中转。

## Decision

加速节点**只缓存不代理**，契约固定为三个端点：

- `POST /v1/cache/lookup` —— 批量查缓存。请求 `items: [{ id, text, sourceLang?, targetLang }]`，响应 `hits: [{ id, translatedText }]`。未出现在 `hits` 中的 id 即未命中。
- `POST /v1/cache/commit` —— 批量 upsert 缓存。请求 `items: [{ id, text, sourceLang?, targetLang, translatedText }]`。**upsert 语义：覆盖既有条目并重置 TTL。**

> **实现偏离（2026-10-07）**：grilling 时定的路径是 `/v1/cache:lookup`（Google 风格冒号）。实测 find-my-way 把冒号后的段当通配参数，导致 `lookup` 与 `commit` 注册到同一路由并抛 `FST_ERR_DUPLICATED_ROUTE`。契约语义不变，路径改为斜杠形式 `/v1/cache/lookup`。ADR 与所有文档统一采用斜杠。
- `GET /healthz` —— 健康检查，供自建者与部署探针使用。

配套决策：

- **缓存条目身份 = 规范化原文 + 源语言 + 目标语言**。规范化（trim / NFKC）与哈希全部由服务端完成，插件不实现哈希算法，避免两端实现漂移。
- **Key 不含 model、不含 customPrompt 指纹。** 加速层定位为通用译文加速层，译文被视为与具体模型无关的结果；当用户配置了非默认 `customPrompt` 时，插件整体跳过加速服务（个性化提示词不属于共享缓存范畴）。
- **用户重试即覆盖公共缓存。** 全文翻译重试路径跳过 lookup，翻译完成后以 upsert 覆盖旧条目——这是纠正错误缓存的唯一手段，且不需要任何鉴权端点。
- **TTL 默认 30 天**，由服务端环境变量配置；文档建议 Redis 配 `maxmemory` + `allkeys-lru`，服务端只负责写 TTL，不自实现淘汰。
- **开放缓存模型**：匿名读、匿名 upsert 写。任何客户端都能覆盖任意条目，信任由用户对自选节点的所有权承担；插件设置页对第三方节点给出明确风险提示（见 ADR-0004）。
- **服务端内置基础限流，按真实客户端 IP 计桶**：`lookup` 限流宽松，`commit` 限流严格（写才是成本大头）。单次请求 `items` ≤ 200 条、单条 `text` ≤ 5000 字符，超限返回 400。**不做 access token**——插件公开分发，官方 token 硬编码即公开；让用户为自建节点填 token 又是无谓的配置负担。
- **限流必须命中真实 IP，部署在 nginx 之后需要显式信任代理**：Fastify 的 `trustProxy` 由 `TRUST_PROXY` 环境变量控制，置为 `true` 时 `request.ip` 取 `X-Forwarded-For` 链最左侧的可信来源。默认 `false`（直连场景按 socket 地址计桶）。**这条必须写进自建文档**——默认配置下所有经 nginx 的自建者会共用 `127.0.0.1` 一个桶，互相把对方限流掉；同时对信任范围内的 `X-Forwarded-For` 盲目取左值会让客户端伪造 IP 绕过限流，故只在确认自己确实位于反向代理之后时才开启。

## Consequences

- 加速节点永远拿不到 API Key，插件隐私承诺在开启加速后依然成立，只需补充说明「原文会发往你选择的加速节点」。
- 错误或低质译文可被任意客户端覆盖，公共缓存没有完整性保证；30 天 TTL 决定了这个窗口的长度。
- 契约只增字段不删字段即可兼容；客户端对响应中的未知 id 必须忽略。
- 限流阈值是**默认建议值而非安全边界**：官方节点的滥用防护最终依赖边缘层（Cloudflare 等）而非本服务；自建节点是自己人，默认值只需防误伤。
- **单条 item 非法时跳过该条、正常处理同批合法条**（非法字段包括缺 `text`/`targetLang`、类型不符、超长等），服务端不因一条坏数据让整批 400——与 fail-open 同构：加速层从严会把个别坏条目放大成全批失败。命中响应中某条缺 `translatedText` 时该条按未命中处理，不升级为 5xx。错误响应统一 `{ error: string }`。
- 插件生成的 `id` 仅作批量回填的相关 id（服务端原样回显），不参与缓存身份；缓存身份只由服务端对 `{text, sourceLang, targetLang}` 的规范化与哈希决定。契约类型落在 `services/relay/src/contracts.ts`，插件与服务共享。

## Alternatives Considered

- **加速节点顺带代理翻译**（服务端持 Key）：命中与未命中一次往返，看似更优，但密钥进入第三方服务、违背插件既有隐私承诺、自建节点成为模型隐形中转。否决。
- **以整批请求为缓存粒度**：任意一段不同即整批失效，全文翻译的分批顺序本身不稳定，命中率趋近于零。否决。
- **Key 绑定 model + customPrompt 指纹**：结果更"正确"，但官方公共缓存命中率会随模型多样性崩塌，加速层失去意义。否决。
- **commit 为 insert-only（先写先赢）**：能挡住覆盖攻击，但错误译文永远无法被纠正，重试也无法改善。否决。
- **需要鉴权的 DELETE 管理端点**：会引入密钥分发问题（插件内无法安全持有共享密钥），而 upsert 已覆盖纠正需求。否决。
